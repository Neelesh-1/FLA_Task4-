
1. Equivalence is undecidable: reduction from the halting problem
-----------------------------------------------------------------
   For a program P build  Q_P(x) = { run P; return 0 }  and  Z(x) = 0.
   Q_P and Z are equivalent  <=>  P halts.  So an exact equivalence checker
   would decide HALT. Three real checkers, three programs P:

   checker_syntax: compares the source code of the two functions
      P = p_halts_now          says NOT EQUIVALENT  truth EQUIVALENT      WRONG
      P = p_halts_after_5000   says NOT EQUIVALENT  truth EQUIVALENT      WRONG
      P = p_loops_forever      says NOT EQUIVALENT  truth NOT EQUIVALENT  right
   checker_testing: runs both on 5 inputs with a 2000-line budget; timeout counts as a difference
      P = p_halts_now          says EQUIVALENT      truth EQUIVALENT      right
      P = p_halts_after_5000   says NOT EQUIVALENT  truth EQUIVALENT      WRONG
      P = p_loops_forever      says NOT EQUIVALENT  truth NOT EQUIVALENT  right
   checker_lenient: same, but inputs that pass the 2000-line budget are skipped
      P = p_halts_now          says EQUIVALENT      truth EQUIVALENT      right
      P = p_halts_after_5000   says EQUIVALENT      truth EQUIVALENT      right
      P = p_loops_forever      says EQUIVALENT      truth NOT EQUIVALENT  WRONG

   Every checker is wrong on some P. Any checker you design will be too.
